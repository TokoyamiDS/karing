# Later the same day — migrated the two sing-box deprecations

User pasted the two startup warnings:

```
WARN legacy special outbounds is deprecated in sing-box 1.11.0 ... removed in 1.13.0
WARN outbound DNS rule item is deprecated in sing-box 1.12.0 ... removed in 1.14.0
```

Both were ours, from `singbox_config_builder.dart`.

**Core version is 1.12.x.** `sing-box version` prints `unknown` (stripped in Karing's
build). Infer it from the warnings: a construct that "will be removed in 1.13" still only
*warns*, so the core is < 1.13; the 1.12 warning puts it at ≥ 1.12. So rule actions are
safe to emit.

## What changed (`singbox_config_builder.dart`)

1. `outbounds()` — `tail` no longer emits `{'type':'block'}` / `{'type':'dns'}`; only
   `direct` remains (`direct` is an ordinary outbound, not a "legacy special" one).
2. `route()` — `outbound: dns-out` → `'action': 'hijack-dns'` (both rules); every
   `outbound: block` → `'action': 'reject'` (Iran ads rule, diversion `case 'block'`, and
   the three serverless refuse-rules).
3. `dns()` — deleted the `{'outbound': 'any', 'server': <direct>}` rule.
4. `route()` — `default_domain_resolver` now prefers an undetoured **`dns-direct-*`**
   server, falling back to the first undetoured one.

**Before removing the outbounds I proved nothing targeted them** — `kGroupTags` excludes
them from group membership, the generated config's selector/urltest contain neither, and
`route.final` is only ever `proxy` or `direct`. So they were purely route-rule targets.

**Two traps I hit:**

- The diversion branch guarded on `if (r.containsKey('outbound'))`. Moving `case 'block'`
  to `action` made that guard **silently drop the rule** — widened to accept either key.
- `serverless_config_test.dart` asserted `['block','block','block',…]` and failed with
  `null`. That is a correct failure; I updated the assertion to the new contract rather
  than reverting the fix.

**Why (4) matters:** the deleted `{'outbound':'any'}` rule was the bootstrap path for
outbound server addresses. `route.default_domain_resolver` is its documented replacement,
so it must prefer the *direct* resolver — otherwise in FakeIP mode bootstrap lands on
`h3://8.8.4.4`, a remote DoH server that is exactly what is blocked in the environments
this app targets.

# "It automatically connects to another VPN" — the selector had no `default`

User: *"its automatically sconnects to another vpn like 🇦🇹 152.53.1.40"*.

## Proven from the running core, not inferred

The app was open, so I asked its Clash API directly (`http://127.0.0.1:3057`):

```
GET /proxies/proxy      -> now = "AutoSelect"          type = Selector
GET /proxies/AutoSelect -> now = "👉…🇦🇹®️A"            type = URLTest   (delay 331)
```

**That is the user's exact symptom, reproduced.** `route.final` → `proxy` → `AutoSelect`
→ the Austrian node.

**Why:** the generated `proxy` selector is
`{type: selector, tag: proxy, outbounds: [AutoSelect, ...tags], interrupt_exist_connections: true}`
— **no `default` field**. sing-box uses a selector's `default` when present, otherwise its
**first** member. The first member is `AutoSelect`, a **URLTest** group that continuously
re-picks the lowest-latency node. So the exit country changes on its own, and the node
chosen in the server list has **no effect at all**.

**The code said so too:** `vpn_service.dart:317` passes `selectOutbound` and `currentTag`
into `outbounds()`, and **neither parameter is read in its body** — `currentTag` appears
nowhere else in the file. A dead parameter on the exact axis that is broken is the
signature of an incomplete refactor (the same tell as the `flutter-test` skill's
"parameter never read in its own body" note).

## Fix

`outbounds()` now emits `default` on the `proxy` selector, derived from the user's current
selection:

```dart
final selectedTag = selectOutbound is Map ? selectOutbound['tag']?.toString() : null;
final selectorDefault =
    (selectedTag != null && selectedTag != kOutboundTagUrltest && tags.contains(selectedTag))
    ? selectedTag : kOutboundTagAutoSelect;
```

Three cases, all deliberate:
- specific node → that node (the actual fix)
- the URLTest group → `AutoSelect`, **not** `urltest`: `getUrltest()` tags itself `urltest`
  but the builder re-tags the emitted group to `AutoSelect`, so copying the tag verbatim
  would leave a dangling `default`
- no selection / tag not among the members → `AutoSelect` (previous behaviour preserved)

Verified against the real core: `sing-box check` on the live config **with `default` added**
→ silent, exit 0.

New `test/selector_default_test.dart` (5 tests): a chosen node becomes the default, the
default is always one of the selector's own members, the urltest group maps to `AutoSelect`,
no selection keeps `AutoSelect`, and `AutoSelect` stays first so the UI order is stable.

**Note the app's own model:** `subscribe_use.json`'s `select_default` is an *observation*,
not a command — `home_screen.dart:780` writes it from `_currentServerForUrltest.now`, i.e.
whichever node the URLTest just picked. So seeing a German node in `select_default` while
traffic exits Austria is consistent, not contradictory.

# Implemented the network usage statistics feature

User: *"i want to see the network usage details … so i can see where have my network gone
mostly. also i want a report even when we stopped the vpn"*.

## What was already there vs. what was missing

The **scaffolding existed but nothing worked**:
- `SettingConfigItemStatistics` — `enable` (default **false**), `dataDesensitize` (default
  true), `cacheDays` (7, max 30), `cacheSizeLimitMB` (1024). Full settings UI in
  `group_helper.dart:995-1096`.
- `PathUtils.statisticsDBFilePath()` → `<profile>/datas/statistics.db`. The `datas/` dir
  exists but **`statistics.db` had never been created** — nothing has ever written it.
- `statistics_records_screen.dart` was a **stub**: an empty `_load()`, an unused `_tables`
  field, and a hardcoded "No statistics available".
- `package:sqlite3` and `sqlite_async` were dependencies, but `sqlite3` appeared **only in a
  commented-out import** (`local_persist_storage.dart:1`). No active usage anywhere.

So both halves were missing: nothing recorded, and nothing read.

## What I built

1. **`lib/app/modules/statistics_manager.dart`** — the persistent store. Table
   `traffic(day, host, process, outbound, upload, download)` with a composite PK, UPSERT
   accumulation, `days()`, `topByHost()`, `topByProcess()`, `totalsFor()`, and `prune()`.
   WAL + `synchronous=NORMAL` (frequent small writes, and a lost tail only costs statistics).
   `open({path})` takes an override so tests use a temp DB; `openReadOnly(path)` gives a
   second handle for the dev "pick a DB file" option so browsing an old file can never
   redirect the recorder's writes.
2. **`lib/app/modules/statistics_recorder.dart`** — polls `/connections` every **2 s** while
   connected, keeps `id -> (upload, download)` from the previous poll, and adds only the
   **delta**. Polling is unavoidable: the core reports only *currently open* connections and
   their byte counts are cumulative per connection, so closed connections vanish and
   re-adding totals would multiply the history on every poll. `pollOnce()` is public so a
   test can drive it without a timer.
3. **`statistics_records_screen.dart`** — real report: day chips built from the days actually
   present (never offers an empty day), totals, then ranked lists by destination and by app,
   each with a proportional bar. Reads only the DB, which is what makes it work with the VPN
   stopped. Distinguishes "nothing recorded yet" from "recording is switched off".
4. **Wiring** — `home_screen.dart` `_startStatistics()` / `_stopStatistics()`, called from
   `_onStateChanged` (transitions only) and from `_checkState`'s connected branch. The latter
   is idempotent and re-arms after a reload cancelled the timers; it is also what picks up
   Statistics being switched on mid-session.

**`dataDesensitize` (default on) reduces a host to its registrable domain** before it is
written — `cdn.a.example.com` → `example.com` — and the process is stored as a basename, not
a full path. IPs are kept as-is (no domain to fall back to).

## Two gotchas worth keeping

- **`package:sqlite3` exports its own `Row`, which collides with Flutter's `Row` widget.**
  In any screen that uses both: `import 'package:sqlite3/sqlite3.dart' hide Row;`.
- **The i18n JSON files carry a UTF-8 BOM.** `json.load(open(p, encoding='utf-8'))` fails with
  *"Unexpected UTF-8 BOM"*; read with `encoding='utf-8-sig'` and write back the same way to
  preserve it. A targeted string insert (not a JSON round-trip) keeps the formatting diff
  clean.

## Verification

- `sqlite3` **does work in `flutter test`** (the native asset is staged) — 8 new tests in
  `test/statistics_manager_test.dart` cover accumulation, ranking order, per-day separation,
  the zero-byte no-op, retention pruning, and the desensitize/process helpers.
- i18n: 5 new keys in the `StatisticsRecordsScreen` namespace, English + Persian, **synced to
  all 28 locales** with identical key sets; `dart run slang` regenerated cleanly.
- **84 tests pass, 0 failures** (per-file). `flutter analyze`: 0 errors.
