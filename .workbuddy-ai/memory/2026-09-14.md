- Answered "how does the SNI connection actually work" and wrote it up as `docs/IRAN-SETUP.md` §7 (Troubleshooting renumbered to §8). Key clarifications, all traced to code: a profile config is a recipe not an endpoint; the scanner tunnels nothing (probes go `scan-in` -> `direct` as the first route rule, so they always measure the physical path); the clean IP is the **entry hop only** and is never the user's public IP; the exit IP is the node's; serverless has no server at all so the visible IP is the user's own ISP IP. Domain-fronting detail: SNI = whitelisted front name (read by the DPI), inner `Host` = real domain (read by the CDN), hence `insecure = true` and hence the front name and the node must share a CDN — which is why the CF-edge verification matters. Applying a scan writes **global** settings re-applied to every CDN outbound at config-build time (round-robin over the IP list), not per-node.
